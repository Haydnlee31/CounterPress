# MatchMind and the supplied Matchday Crew video: source audit

## What the two references actually implement

### Takeaway
The video and GitHub link refer to **different projects**. MatchMind has six pipeline roles, three backed by language models through Microsoft Agent Framework; the video is Matchday Crew, which registers three prompt agents in Foundry. Both orchestrate their stages in application code. Neither inspected implementation watches real match video or delegates football measurements to an LLM.

### Cited Findings
- Audit date: 26 October 2026. MatchMind source pinned to commit `3be1f22d66b880cc9501a15f31101b445f947c4b`; Matchday Crew to `374de95f4f7474c9a784e01a3ceafb2ce0a16ad5`. The complete recursive trees contained 66 and 50 files respectively. Source was inspected through the GitHub connector; no third-party code was executed. [MatchMind tree](https://api.github.com/repos/auroraeye-dev/matchmind/git/trees/3be1f22d66b880cc9501a15f31101b445f947c4b?recursive=1), [Crew tree](https://api.github.com/repos/timsheldon1/matchday-crew/git/trees/374de95f4f7474c9a784e01a3ceafb2ce0a16ad5?recursive=1)
- The supplied video is titled **“Matchday Crew: AI agents that explain live football in English, Swahili and Japanese”**, author Timsheldon Oure, duration 111 seconds. Its description points to `timsheldon1/matchday-crew`, not `auroraeye-dev/matchmind`. This was verified from the actual YouTube HTML/player metadata, retrieved successfully after ordinary web fetches failed. [Video](https://www.youtube.com/watch?v=HxED-0T8Unw)
- **Video verification limit:** page metadata, description and author chapter markers were retrieved. Japanese autogenerated captions were advertised, but their endpoint returned empty content; the English translated-caption attempt returned HTTP 429. No video frames or audio were inspected. Therefore the following are **author-provided chapter markers, not independently observed demonstrations**: 0:00 why built; 0:13 live match/AI commentary; 0:30 analyst view/handoff; 0:50 Swahili goal call; 1:12 Japanese halftime recap; 1:27 guardrails; 1:42 Azure. [Video](https://www.youtube.com/watch?v=HxED-0T8Unw)
- MatchMind roles: **Vision** reconstructs events from ball tracking; **Interpreter** calculates statistics and flags moments deterministically; **Explainer** writes why; **Narrator** writes commentary/recaps; **Personalizer** ranks/rephrases per viewer; **Renderer** emits timed graphics deterministically. Only Explainer, Narrator and Personalizer are Agent Framework LLM agents. Roles are cached by role/instructions; Foundry is a `FoundryChatClient`, with managed-identity credentials. [Provider L52–116](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/llm/provider.py#L52), [Orchestrator L35–50](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/orchestrator.py#L35)
- MatchMind's stage graph is Python `Orchestrator` code: interpreter inline per event, asynchronous per-moment Explainer→Narrator→per-persona Personalizer→Renderer. Persona fan-out uses `asyncio.gather`. Six pending moments trigger low-importance LLM shedding. This is not a deployed Foundry Workflow. [Orchestrator L79–135](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/orchestrator.py#L79)
- MatchMind event mode lazily yields generated events and paces them through a WebSocket. Tracking mode first materializes the synthetic event list, renders it into tracking frames, then reconstructs/paces detected events. It is incremental event processing on synthetic input, not video upload processing. [Server L155–208](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/server.py#L155)
- Its “Vision” consumes `{t,x,y,z,possessor_id,possessor_team}` ball frames at 10 Hz, plus official cards/fouls/substitutions/restarts/period markers. The feed adds Gaussian position noise (default 0.15 m), 1% dropped frames, 0.4% possessor flicker. It does not contain footage pixels, camera calibration, object detection, player recognition or a full 22-player position stream. [Frame contract L20–37](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/sim/tracking.py#L20), [Feed L106–139](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/sim/tracking.py#L106)
- Vision detects pass success/failure/out, interceptions, tackles, possession changes, shots/goals/saves from known possession and ball-flight changes. Shot identification uses a 13-feature logistic classifier; goals use line-crossing geometry. The classifier features include peak speed, start/end goal distance, directness, starting xG, flight length, height, receiver type and crossed boundary. [Vision L105–239](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/agents/vision.py#L105)
- The classifier is trained on the same simulator family (seeds 101–140: 38,526 flights/1,250 shots); validation 201–210 has 9,644 flights/306 shots, recorded F1 .955, recall .961, precision .948, threshold .42. Repository submission claims a separate 20-seed test with 100% goal precision/recall and 99% shot precision. The first figures are checked-in model metadata; the latter are author claims, not independently rerun here. This does not establish real-video performance. [Model JSON](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/agents/vision_model.json), [Training L28–40, L95–123](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/agents/vision_train.py#L28), [Submission L20–24](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/docs/SUBMISSION.md#L20)
- MatchMind exposes seven MCP tools: `get_match`, `get_match_state`, `list_moments`, `explain_moment`, `personalize_moment`, `get_player_tag`, `get_events`; resource `matchmind://schema/event`. These replay seeded generated matches; explanation/personalization tools use rules, not live LLM calls. `_find` replays the whole match before explaining a historical moment. [MCP L39–138](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/mcp_server.py#L39)
- MatchMind integration implementations include Cosmos match/moment/overlay storage; optional Fabric Eventstream via Event Hubs-compatible producer; asynchronous bounded sink queues; Translator; and a Copilot SDK postmatch report client with read-only MCP tools. KQL examples visualize xG race, momentum/chaos and top difficult passes; two example queries are hardcoded to match `SYN-00289`. Deployment existence/cost was not tested. [Sinks](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/integrations/sinks.py), [Reporter](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/matchmind/copilot_reporter.py), [KQL](https://github.com/auroraeye-dev/matchmind/blob/3be1f22d66b880cc9501a15f31101b445f947c4b/fabric/matchmind.kql)

### Inferences
- The user's interpretation of specialists independently watching footage exceeds what either supplied reference demonstrates in inspected code. The useful pattern is deterministic match intelligence feeding specialist interpretation and presentation agents.
- Actual Foundry-native workflow orchestration would be a deliberate improvement beyond both repositories, not a port of an existing implementation.
- MatchMind's mutable shared MatchState can advance during awaited LLM stages; downstream snapshots can contain information later than the triggering moment. Footie should use immutable event-watermark snapshots, and exclude future replay data from all specialist tools.

### Gaps
- No independent runtime test, benchmark rerun, live deployment verification, video watch or reliable caption transcript was obtained. Treat model quality/latency results as author-reported unless separately reproduced.

## Exhaustive MatchMind metric and moment inventory

### Takeaway
All measurements are supplied synthetic values or deterministic calculations. Several useful fields have narrower meanings than their names imply: event-location heatmaps, a whole-pitch PPDA proxy, elapsed-time distance estimates and event-count sprint estimates. Reproduce capability coverage with explicit definitions and quality metadata, not these assumptions blindly.

### Inferences
- Require missing/unsupported rather than zero for xG/speed/distance/pressure when inputs are absent. The reference's tracking path cannot supply all event-path metrics without extra inputs.
- A continuous player-position source is necessary for genuine off-ball heatmaps, team compactness, line height, speed, runs and distance. Authored replay animation is insufficient as measured evidence. It can be explicitly modeled telemetry in a dedicated synthetic scenario.
- Use conventional geometry/time definitions and independently tested reducers. Reference formulas are design inspiration, not empirically validated models to copy.

### Gaps
- No externally fitted xG/pass model, real video detector, real-world tracking evaluation or position-specific calibration dataset was found in the inspected MatchMind tree.

## What to adapt from Matchday Crew and what to improve for Footie

### Takeaway
The strongest additions are registered, inspectable Foundry agents; controlled live prioritization; persistent context to prevent repetition; and output contracts that force a meaningful consequence and next observable test. Agent quantity is not the core improvement. Keep deterministic metrics separate from model interpretation and make specialist disagreement useful.

### Cited Findings
- Crew registers **Explainer**, **Storyteller**, **Recapper** using `project.agents.createVersion(kind:'prompt', model, instructions, strict JSON schema)`. It obtains and caches explicit versions and calls `responses.create` using `agent_reference`. On selected400/404 failures it tries a direct model call; after three such failures that role stays direct until restart/redeploy. [Foundry L34–87/L125–181](https://github.com/timsheldon1/matchday-crew/blob/374de95f4f7474c9a784e01a3ceafb2ce0a16ad5/src/agents/foundry.js#L34)
- Crew handoffs remain in Node `createCrew`: priority queue, max3 concurrent jobs, backlog6, per-role timeouts9/11/30 seconds. Important goals/recaps/red cards/penalties are preserved. Noncritical waiting jobs may be dropped. Moment/snapshot are submitted together. Recent three insights and four displayed lines are passed onward to reduce repetition. [Crew L18–27/L110–151/L232–257](https://github.com/timsheldon1/matchday-crew/blob/374de95f4f7474c9a784e01a3ceafb2ce0a16ad5/src/agents/crew.js#L110)
- Explanation contract: why≤40 words, tactical angle≤25 words, one-to-three key numeric facts, high/medium/low confidence. Storyteller produces≤25-word native-language lines per audience, preserving names. Recapper gets top players and prior important explanations. Prompts include a domain-specific Swahili glossary and linguistic guidance; source says native-speaker-reviewed. [Agent definitions](https://github.com/timsheldon1/matchday-crew/blob/374de95f4f7474c9a784e01a3ceafb2ce0a16ad5/src/agents/definitions.js)
- Crew deterministically tracks team goals/xG/shots/on-target/big chances, passes/completions/final-third entries/box entries, carries/sprints/pressures/tackles/won/interceptions/high recoveries, fouls/yellow/red/corners/saves/possession. Player additions include key passes, progressive passes, carry distance, sprint count, top speed, saves/cards and a heuristic3–10 rating. Moment set adds goal-state context (opener/equalizer/go-ahead/lead extension/pullback/against-run-of-play), xG-vs-score, penalties, red cards, high-recovery pressing spells, speed/shot-speed/quality-pass alerts. [Analyst L15–48/L144–317/L350–486](https://github.com/timsheldon1/matchday-crew/blob/374de95f4f7474c9a784e01a3ceafb2ce0a16ad5/src/analyst.js#L15)

Rhythm uses turnover rate; pressing requires pressure and high recoveries. xG-versus-score requires at least1.0 xG advantage but no score lead after30 minutes. Values are heuristics. ### Inferences
- Suggested distinct analysis responsibilities: **Chance & finishing** (quality/location/creation/outcomes), **Possession & progression** (routes/losses/territory), **Press & transitions** (pressure→recovery→threat), **Player impact** (involvement/roles/career context), followed by **Footie editor/verifier** to reconcile and publish. These differ from the reference's mostly presentation-oriented role split.
- A useful card should state a supported pattern, why it changes the game, a counterpoint or uncertainty, and a specific next thing to watch. Example structure: “More of the ball, less danger” → evidence window and comparison → failed routes or low-value shot pattern → “Watch whether the next possessions enter the box.” Do not invent coach intent or guaranteed future outcomes.
- Pin all agents to one as-of event/revision watermark; carry claim IDs, event IDs, metric definitions and availability through every handoff. Verify entity/time/units and entailment, not just numeric membership. Give a critic the ability to abstain rather than rewrite weak evidence into confidence.
- Use one live editorial lead, a few quietly updating specialist status/lens tabs, and an evidence timeline tied to replay. This offers a creative new analyst workspace without adding six competing chat feeds or overwhelming mobile users.
- Avoid model work every frame/event: cheap reducers update continuously; meaningful state-change triggers dispatch only needed specialists; deduplicate/coalesce repeated windows; cache analyses by match+revision+watermark+persona; enforce deadline/staleness expiry and cost guard.
- Comparison tests should cover unseen match windows, no-future-information, no unsupported tracking claims, numeric/entity correctness, bland event-description rejection, evidence-linked useful implications, stale output after seek, cancellation, agent failures, latency and spend. Visual checks must ensure cards/tags do not obscure the pitch.

### Gaps
- The current official Foundry Workflow/agent orchestration capability and regional support are covered by the parallel Azure research task; these repository examples are not sufficient to select a current API/version.
- Crew's real deployment configuration, actual model calls during the video and video voice quality were not independently verified. Metadata and code support architecture findings; no claims of having watched/listened are made.
